## Anti-Patterns Verdict

**LLM assessment**: Does not feel AI-generated. Animated SVG baguette is distinctive. Terracotta/cream palette is committed and specific. Source pills are an unusually transparent design choice. Tooltip content references actual baking science (Hamelman, DDT, Newton's law) rather than filler copy. No gradient text, glass cards, or numbered section markers.

One genuine spec violation: `.group-label` uses `text-transform: uppercase` with `letter-spacing: 0.1em` — literally the "tracked-caps eyebrow on every group" pattern the design spec's own absolute-bans list prohibits. Reads as AI scaffold even though the rest of the design doesn't.

**Detector scan**: `[]` — clean, zero findings.

## Overall Impression

A strongly characterised, single-purpose tool. The flour-cascade architecture surfaces meaningfully in the UI via source pills and flour-driven defaults. Main friction is concentrated in three spots: labels (jargon on advanced controls), tip-open behaviour (question vanishes when you need it), and touch targets on smaller interactive elements.

## What's Working

1. **Source pills** ("auto · from Miller & Baker") — genuinely transparent. Users see which values are formula-driven vs. overridden without a settings screen.
2. **Animated oven-spring hero** — the SVG baguette is distinctive and on-brand without shouting.
3. **Progressive disclosure** — essentials visible by default, advanced one tap away. Well-calibrated for a kitchen app.

## Priority Issues

**[P1] Tracked-caps group labels ("BATCH", "DOUGH", "ENVIRONMENT")**
The design spec's own absolute-bans list prohibits "tiny uppercase tracked eyebrow above every group." These labels are exactly that pattern.
Fix: Remove `text-transform: uppercase` and `letter-spacing` from `.group-label`; use regular-case ("Batch", "Dough", "Environment") or a coloured dividing line.
Command: /impeccable typeset

**[P1] Touch targets below 44px on primary nav elements**
`.info-btn` is 20×20px (the "?" method comparison button). Stage pills render ~28px tall (padding 5px 11px). Both are primary interactive elements on a phone-first app.
Fix: `.info-btn` → expand hit area to 44×44px with padding. Stage pills → `padding: 10px 11px` (up from 5px).
Command: /impeccable audit

**[P2] Tip hint disappears on open**
`.tip.open .tip-hint { display: none }` — the question ("Why this hydration?") vanishes the moment the answer appears.
Fix: Remove `display: none`; keep the hint visible as a persistent label above the body. Style it muted/smaller on open rather than hidden.
Command: /impeccable polish

**[P2] Jargon on labels without explanation affordance**
"Fermentolyse (min)", "τ (tau)", "Bench-rest floor (min)" require prior knowledge. Tips explain them well but there's no visible cue that a tip exists before seeing the collapse affordance.
Fix: Plain-English renames where sensible: "Pre-mix rest (min)", "Minimum bench rest". For τ, expose the hint text always as a static line below the label.
Command: /impeccable clarify

**[P2] .src and .tip-toggle below 44px**
`.src` pills ~20px tall. `.tip-toggle` renders ~32px. Both misfire-prone on mobile.
Fix: `.tip-toggle` → `min-height: 44px`. `.src` pill → wrap the label row in a larger tap area or make the whole label row tappable.
Command: /impeccable audit

## Minor Observations

- `.src` reset confirmation is instant and easy to miss — a brief text-flash or opacity change would make it feel more intentional
- `h2` and accent elements share `color: var(--accent)` — fine for consistency but worth watching if the terracotta starts to lose hierarchy weight
- `.stages-bar` `border-radius: 0 0 16px 16px` may create a seam between `.head` and `.stages-bar` on some browsers when it first sticks — worth a visual check
- Hero hydration number updates immediately on control change ✓

## Questions to Consider

1. "Fermentolyse" appears on the control label AND as a step title in the recipe — is precision worth the accessibility tradeoff, or could "Pre-mix rest" in the control + "Fermentolyse" in the step header satisfy both audiences?
2. Does the flour blend UI simplify if the % number inputs are removed and only the slider + select labels show the split?
3. While fixing the tip-hint disappearing issue, is the overall tip visual pattern (cream bg, +/− prefix) the right container — or would a more subtle inline footnote style serve better?
